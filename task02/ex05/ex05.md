# Part 3
When using NumPy with a `uint8` image, adding 100 can cause overflow. The pixel values are limited to 0–255, so values above 255 wrap around instead of being clipped to 255. For example, 200 + 100 becomes 44. This is why some bright areas become dark.

# Part 4
When `b = -100`, NumPy raises an `OverflowError` in my NumPy version when adding a negative integer to a `uint8` image.

OpenCV uses `cv2.subtract` to subtract 100 from each pixel. Pixel values below 0 are clipped to 0.

The `add_safe` method also subtracts 100 from each pixel and clips the result to the range 0–255.

# Part 5
Without `vmin` and `vmax`, Matplotlib automatically scales the pixel values of each image using its own minimum and maximum values. As a result, the images may look different compared to Part 2. With `vmin=0` and `vmax=255`, all images use the same intensity range, making their brightness easier to compare.
